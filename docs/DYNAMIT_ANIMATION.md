# Dynamit Bot — плавный цикл бега

Версия 0.52.2-dynamit-faster-run, 22 октября 2026.

По просьбе автора цикл расширен с 8 до **48 кадров** в каждом направлении.
Корпус и детали взяты из утверждённого спрайта `run_01.png`. Ноги собраны
из отдельных жёстких деталей: бедро, голень и стопа; положение коленей
рассчитывается по постоянным длинам сегментов. Корпус сохраняет форму,
вертикальное движение ограничено тремя пикселями исходного холста.
Хотя бы одна стопа опирается на землю; перенос второй проходит по плавной кривой.
Последний кадр непрерывно переходит в первый. Смешивания силуэтов нет.

48 правых PNG и 48 точных отражений имеют одинаковый прозрачный холст 444×444.
Экспорт воспроизводится `tests/export-dynamit-run.py` (Pillow). Исходные восемь
кадров сохранены как авторский материал, в беговом состоянии используются новые.

Фаза шага зависит от пройденного расстояния, включая скорость отряда.
Клиентский `OnUpdate(delta)` интерполирует фазу между тактами симуляции 25 Гц:
добавленные кадры видны между тактами, а не только при замедленном движении.
Переключение спрайтов локальное для каждого устройства, не создаёт эффектов
и не меняет симуляцию. После остановки, EMP и взведения фаза не продолжается.
Уничтоженные устройства удаляются из кэша. Остановленная поза и подрыв сохранены.

Автопроверка покрывает промежуточные позы между тактами, независимость сторон,
остановку/EMP/взведение, очистку кэша и привязку прозрачных ресурсов.
Нативная проверка свежим процессом Forts проводится отдельно; результаты
записываются в DEVELOPMENT_STATUS.md. Проверки синтаксиса не заменяют просмотр.

## Принятое правило для следующих шагоходов

Автор одобрил этот цикл 22 октября («идеально») и попросил повторять подход.
Ноги делить на жёсткие сегменты с постоянными шарнирами; колено рассчитывать
по двум неизменным длинам. Корпус сохраняет силуэт; стопы не растягивать.
Использовать не меньше 48 промежуточных поз, плавный перенос стопы, опору
хотя бы одной ноги и непрерывный переход последнего кадра в первый.
Разные исходные рисунки не смешивать: это даёт двойные контуры.
Зеркальную сторону получать точным отражением готового кадра.
Движение задаёт фазу шага, OnUpdate(delta) сглаживает её между тактами.
Не создавать эффекты/устройства ради каждого кадра и не продолжать бег при EMP.

После одобрения цикл ускорен **в 2 раза**: AnimationStride 140 → 70.
Скорость перемещения осталась 2,5 шахты/с; 48 кадров сохранены.
